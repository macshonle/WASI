# Claude Code Agent Instructions

This document provides instructions for Claude Code agents working on implementing WASI in C.

## Environment Setup (GNU/Linux)

### Required Tools

Before generating or working with C bindings, verify the following tools are installed:

```bash
# Check tool availability
which wasm-tools && wasm-tools --version
which wit-bindgen && wit-bindgen --version
which wit-deps && wit-deps --version

# Check C compiler
which gcc && gcc --version
# or
which clang && clang --version
```

### Installing Tools (if missing)

```bash
# Install Rust toolchain first (if not present)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env

# Install the WIT/WASM tools
cargo install wasm-tools wit-deps-cli wit-bindgen-cli

# Verify installation
wasm-tools --version    # Should show version
wit-bindgen --version   # Should show version
wit-deps --version      # Should show version
```

### Test Tool Functionality

Run these commands to verify the tools work correctly:

```bash
# Test 1: Generate C bindings for a simple proposal (io has no dependencies)
make clean
make v0.2.0

# Expected output: build/c-bindings/ populated with .c, .h, and .o files

# Test 2: Verify generated files exist
ls -la build/c-bindings/io/
# Should show: imports.c, imports.h, imports_component_type.o

# Test 3: Check that headers are valid C
gcc -fsyntax-only -c build/c-bindings/io/imports.h 2>&1
# Should produce no errors (warnings are OK)

# Test 4: Compile the generated C file
gcc -c build/c-bindings/io/imports.c -o /tmp/test-imports.o -I build/c-bindings/io/
# Should succeed
```

## Implementation Approach

### Step 1: Start with `wasi:io` (simplest, no WASI dependencies)

The `io` proposal is the foundation. It defines:
- `error` - Error handling resource
- `poll` - Async polling with pollables
- `streams` - Input and output streams

Start here because other proposals depend on it.

### Step 2: Implement `wasi:random` (also no dependencies)

Simple random number generation:
- `get-random-bytes` - Get N random bytes
- `get-random-u64` - Get a random 64-bit integer
- `insecure` variants for non-crypto uses

### Step 3: Implement `wasi:clocks` (depends on io)

Time-related interfaces:
- `monotonic-clock` - Monotonic (always increasing) time
- `wall-clock` - Calendar time

### Step 4: Continue with remaining proposals

Dependency order:
1. `io`, `random` (no deps)
2. `clocks` (depends on io)
3. `filesystem` (depends on io, clocks)
4. `sockets` (depends on io, clocks)
5. `cli` (depends on io, clocks, filesystem, random, sockets)
6. `http` (depends on io, cli, clocks)

## Key Patterns in Generated Code

### Resource Handles

WASI uses opaque handles for resources:

```c
typedef struct wasi_io_streams_own_input_stream_t {
  int32_t __handle;
} wasi_io_streams_own_input_stream_t;
```

You'll need to implement a handle table to map these to actual OS resources (file descriptors, etc.).

### Strings

WASI strings are pointer + length (not null-terminated):

```c
typedef struct imports_string_t {
  uint8_t *ptr;
  size_t len;
} imports_string_t;
```

### Results and Options

Results use a tagged union pattern:

```c
typedef struct {
  bool is_err;
  union {
    some_type_t ok;
    error_type_t err;
  } val;
} some_result_t;
```

### Functions to Implement

Look for `extern` declarations in the generated headers - these are the functions you must implement:

```c
// Example from wasi:random
extern void wasi_random_random_get_random_bytes(uint64_t len, imports_list_u8_t *ret);
extern uint64_t wasi_random_random_get_random_u64(void);
```

## Testing Guidelines

### Unit Test Structure

```c
// tests/test_random.c
#include <stdio.h>
#include <assert.h>
#include "../build/c-bindings/random/imports.h"

void test_get_random_u64() {
    uint64_t a = wasi_random_random_get_random_u64();
    uint64_t b = wasi_random_random_get_random_u64();
    // Random values should (almost certainly) be different
    assert(a != b);
    printf("test_get_random_u64: PASS\n");
}

int main() {
    test_get_random_u64();
    return 0;
}
```

### Running Tests

```bash
# Build and run tests (once implementation exists)
make test
```

## Platform-Specific Notes

### Linux

- Use `/dev/urandom` for random bytes
- Use `clock_gettime()` for clocks
- Use standard POSIX APIs for filesystem/sockets

### macOS (Darwin)

- Use `arc4random_buf()` for random bytes (preferred over /dev/urandom)
- Use `clock_gettime()` (available since macOS 10.12)
- Use standard POSIX APIs for filesystem/sockets

## Incremental Development Strategy

1. **Generate bindings first**: `make v0.2.0`
2. **Read the generated header** to understand the interface
3. **Create a skeleton implementation** with stub functions
4. **Implement one function at a time**
5. **Write a test for that function**
6. **Verify test passes**
7. **Move to next function**
8. **Commit working code frequently**

## Common Issues

### "undefined reference" errors

You need to implement all `extern` functions declared in the headers.

### Handle management

Create a simple handle table:

```c
#define MAX_HANDLES 1024
static void *handle_table[MAX_HANDLES];
static int next_handle = 1;

int32_t allocate_handle(void *resource) {
    if (next_handle >= MAX_HANDLES) return -1;
    handle_table[next_handle] = resource;
    return next_handle++;
}

void *get_resource(int32_t handle) {
    if (handle <= 0 || handle >= MAX_HANDLES) return NULL;
    return handle_table[handle];
}
```

### Memory management

The generated code uses specific allocators. Check the generated `.c` file for `__wasm_import_*` functions that may need implementation.
